# Phase 46 - 跨设备附件目录与生命周期

## 1. 背景与动机

Phase 45 已允许客户端显式上传附件，但服务端只有创建会话和 complete 接口，
其他设备无法发现附件，删除本地记录也不会清理云端对象。本阶段补齐附件目录
读取、下载和删除生命周期。

## 2. 目标 / 非目标

### 目标

- **G1**：附件表记录原始文件名，数据库 migration 兼容历史数据；
- **G2**：新增账本级附件列表 API，返回元数据和短期下载 URL；
- **G3**：新增附件删除 API，先删除对象再删除元数据；
- **G4**：客户端启动附件页时拉取远端 ready 附件；
- **G5**：远端新附件按原始字节下载并写入本地附件库；
- **G6**：远端已删除的附件从本机清理；
- **G7**：客户端删除已上传附件时同步删除远端对象；
- **G8**：本地账本未绑定或绑定到其他远端账号时禁止合并和删除；
- **G9**：local-only 模式仍不访问远端 API。

### 非目标

- 不对附件做字段级冲突合并；服务端目录是远端权威状态；
- 不自动下载 pending/failed 附件；
- 不实现缩略图下载、multipart 或断点续传；
- 不允许客户端指定 object key。

## 3. 服务端 API

### 列表

```http
GET /v1/books/{bookId}/attachments
```

返回：

```json
{
  "attachments": [{
    "id": "...",
    "transactionId": "...",
    "fileName": "receipt.jpg",
    "objectKey": "books/...",
    "contentHash": "...",
    "mimeType": "image/jpeg",
    "sizeBytes": 12345,
    "uploadStatus": "ready",
    "createdAt": "2026-09-14T00:00:00Z",
    "downloadUrl": "https://...",
    "downloadMode": "direct"
  }]
}
```

只有 `ready` 项包含下载 URL。历史数据没有文件名时返回 `attachment`。

### 删除

```http
DELETE /v1/books/{bookId}/attachments/{attachmentId}
```

删除顺序固定为对象存储优先、数据库其次，避免数据库先删后留下不可追踪对象。
删除成功后返回 `204`，重复删除返回 `404`。

## 4. 客户端合并

```text
打开附件页 / 交易附件面板
  -> 检查本地 book 与远端账号绑定
  -> GET 远端附件目录
  -> ready 且本地不存在：下载字节并写入本地
  -> ready 且本地存在：校验大小并刷新元数据
  -> 本地 ready、远端已不存在：清理本地记录和字节
  -> 保持 Local-first UI 数据源不变
```

本地账本尚未绑定远端时不做目录合并，避免把其他账号的附件误写入当前账本。

## 5. 删除语义

- 仅本机附件：直接删除本地元数据和字节；
- 已上传附件：先调用服务端删除，再删除本地；
- 服务端已返回 `404` 时视为删除成功；
- 服务端删除失败时保留本地附件，让用户重试；
- 上传中断留下的 pending/failed 服务端记录可在列表页删除。

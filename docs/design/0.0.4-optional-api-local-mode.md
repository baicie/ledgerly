# Optional API and local-only mode for 0.0.4

* Branch: `codex/optional-api-local-mode-0.0.4`
* Target: `v0.0.4`
* Status: Ready for release

## Goal

Make the API origin optional. An installation with no configured origin must
remain a complete local ledger backed by Drift and must not construct or invoke
remote authentication or synchronization. Users can opt into a server later
without losing local ledger data.

## Product contract

* No saved or embedded origin starts in local-only mode on every build type.
* A saved non-empty origin takes precedence over the optional
  `LEDGERLY_API_BASE_URL` build default.
* A saved blank value explicitly selects local-only mode and overrides an
  embedded default.
* Local-only mode enters the application shell directly. It does not show the
  login or startup restoration pages.
* Feed, accounts, local reports, local export, and local writes keep using the
  existing Drift database.
* Remote report loading, synchronization controls, transaction revisions,
  subscriptions, sharing, server budgets, server FX rates, recurring jobs, and
  attachments remain inactive until an origin is configured and authenticated.
* Settings displays the active storage mode. Users can add, replace, or clear
  the API origin.
* Clearing an origin while authenticated logs out from the old origin before
  persisting local-only mode. Adding an origin from local mode does not perform
  a meaningless local logout and opens the remote authentication flow after the
  endpoint-keyed scope is rebuilt.
* Invalid non-empty saved configuration still opens recovery instead of
  silently contacting an embedded fallback. Recovery accepts blank input to
  select local-only mode.

## Persistence and isolation

The endpoint preference has three meaningful persisted states:

1. Missing: use a non-empty build default, otherwise local-only mode.
2. Blank: local-only mode, overriding any build default.
3. Non-empty: validate and normalize the configured remote origin.

The same Drift database remains the UI's business-data source in both modes.
The Riverpod dependency scope is keyed by `local` or the normalized API origin,
so changing modes closes the old database handle and network clients before
reopening dependencies. Local device identity uses a dedicated local namespace;
remote device IDs and authentication material remain namespaced by API origin.

## Network boundary

`AuthController.local()` has no `AuthGateway`. The local branch of
`authControllerProvider` therefore cannot restore a cookie or refresh token and
cannot construct `AuthRepository` or Dio. Report and sync pages check mode before
reading their remote providers, and local feed rows do not open the remote
revision flow. This makes absence of network activity a dependency invariant,
not a best-effort error path.

## Release and verification

Client version is `0.0.4+4`, with release tag `v0.0.4`. The existing release
workflow continues to accept an empty `LEDGERLY_API_BASE_URL`, packages Web and
three signed Android APKs, publishes the server image, and does not deploy the
server automatically.

Acceptance evidence must include:

* controller tests for missing, blank, embedded, invalid, and failed-persistence
  endpoint states;
* provider tests proving local startup does not read the remote auth repository;
* router and bootstrap tests proving local mode bypasses authentication;
* page tests proving local feed, reports, and sync center do not expose or read
  remote synchronization;
* widget tests proving remote-to-local switch order and remote settings gating;
* Flutter formatting, analysis, all client tests, Web release build without an
  API define, package tests, and server checks;
* squash merge into `main`, successful `v0.0.4` Release assets and GHCR tags,
  followed by feature branch and worktree cleanup.

## Rollback

No database or server migration is introduced. Reverting the client behavior
restores the 0.0.3 mandatory-configuration screen but does not delete local
ledger data. A saved blank endpoint may require users to enter a server origin
again after rollback.
